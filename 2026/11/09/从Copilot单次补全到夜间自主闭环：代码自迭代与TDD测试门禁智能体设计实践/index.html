从 Copilot 单次补全到夜间自主接力：基于 TDD 门禁与隔离沙箱的代码自迭代智能体实践

发表于 2026-11-09 更新于 2026-11-14 分类于 技术实践

大一刚入学参加岳麓黑客松时，我还只写过两个月代码，连调外部 API 都得跟着学长一步步摸索；当时我在随笔里写过一句偏感想的话，觉得做应用只要学会把现成 AI 能力串起来就行。

转到大二上学期，刚在先导杯里啃完海光 DCU 上的算子与推理优化，这几天又在跟进 世界计算大会 × 昆仑元 × AMD 黑客松。这次赛制里最戳我的环节是 “24h 碳硅接力 / 夜间自主研发”——白天由人类定义任务队列、接口骨架与测试契约，夜间选手全部撤场，让 Agent 在本地算力或网关节点（如昆仑 GPT-Factory One / AI Agent Gateway、AMD Ryzen AI MAX+ 395 本地推理等）上无人值守自主编码、自测、纠错、回滚，第二天早上人类直接拿交接报告接续推进。

yysy，平时用 Copilot 或 Cursor 写代码时，我们很容易低估自己充当了多少“人肉胶水”：模型给一段补全，人手动点 Accept、切终端跑单测、把 Traceback 贴回对话框再改。真到夜间撤场跑自主循环时，没有强约束马上会翻车：要么死循环把 Token 烧干，要么模型为了“让单测通过”直接去改测试断言；而更隐蔽的翻车点，则是我 11 月 9 日写第一版原型后回头审代码时暴露出来的那一堆工程欠账——没有路径逃逸校验、测试跑在原工作区没有只读隔离、单文件全量覆写、以及拿 round(..., 6) 去冒充 0-ULP 精度。

这几天我把这套 ACS-Agent（Autonomous Code Synthesis & Verification Agent） 彻底重构了一遍，开源在 GitHub：https://github.com/aarchyyy/autonomous-code-agent。新版核心引擎与实时工作台完全基于 Python 3.9+ 标准库（零第三方强制依赖），补齐了 PathGuard 路径与软链拦截、临时只读副本 + 密钥脱敏 + python -I + RLIMIT 沙箱、SHA-256 门禁完整性核验、多文件 ReAct 与双协议降级、最佳分数回滚与防停滞熔断、隐藏 Holdout 防过拟合、以及 24h 夜间接力编排与晨间交接简报。目前 23 项框架与对抗性单元测试全部通过（6.003s），这篇就把重构前后的工程对比、核心模块实现和真实验证边界一次记清楚。

一、 从“原型漏洞清单”到 24h 碳硅接力的工程进化

在 11 月 9 日初版复盘里，我列出了当时原型暴露的几项硬伤：文件写入没有原子替换、_resolve_path 没拦截 .. 穿越、测试直接在宿主机原目录跑、没有测试前后哈希校验、Case 1 缺负索引检查、Case 2 用 round(..., 6) 充数等。这次重构直接按“人夜间真的敢撤场”的标准，把这些问题逐项用代码填实：

二、 分层隔离沙箱与防作弊边界：src/sandbox.py

要让 Agent 在夜间自由修改代码而不搞坏仓库，核心防线全部收敛在 src/sandbox.py 的四个核心组件中。

2.1 PathGuard：封死目录穿越、软链逃逸与隐藏测试窥探

早期的路径解析没有做 realpath 前缀约束，很容易被 ../ 或符号链接绕过。现在的 PathGuard 在每次读写前都会走一遍 canonicalize：

  1. 符号链接与逃逸拦截：将相对或绝对路径统一通过 os.path.realpath 解析到真实物理路径（即使目标文件尚未创建，其父目录若是指向工作区外的软链同样会被 realpath 展开），随后校验 os.path.commonpath([self.workspace_root, real_candidate]) == self.workspace_root。
  2. 读写访问控制矩阵（ACL）：
    • 任何访问 .git 或 .acs_runs 目录内部路径的请求直接抛出 PathSecurityError；
    • hidden_files（隐藏 Holdout 测试）在 check_read、list_files、search_code 中彻底不可见，且在 include_hidden=False 时禁止通过 run_tests 触发；
    • check_write 强制拦截 protected_files（可见测试文件）并校验文件必须落在 writable_files 授权白名单内。

2.2 IsolatedTestRunner：临时只读副本、环境变量清洗与进程组看门狗

即便限制了 Agent 的写权限，待测代码本身在 unittest 运行时也可能顺手往当前目录写垃圾文件、试图修改测试文件、读取宿主机环境变量里的 OPENAI_API_KEY，或者陷入死循环。IsolatedTestRunner.run_tests 做了五层隔离：

具体运行行为：

  • 临时只读副本：默认将工作区复制进 tempfile.TemporaryDirectory（跳过 .git、__pycache__ 等目录，并在常规 TDD 阶段直接不复制 hidden_files）；所有 protected_files 与 hidden_files 在临时目录内设为 0o444 只读。
  • 密钥脱敏与隔离模式：_sanitized_subprocess_env() 过滤掉名称包含 KEY、TOKEN、SECRET、PASS、CREDENTIAL、AUTH、COOKIE、SESSION、PRIVATE 的环境变量，附加 PYTHONNOUSERSITE=1 与 PYTHONDONTWRITEBYTECODE=1，并以 python -I 启动。
  • 资源限额与进程组强杀：子进程引导器在执行 unittest 前通过 resource.setrlimit 施加 RLIMIT_CPU（默认 15s）与 RLIMIT_FSIZE（默认 16MB，Linux 下额外加 RLIMIT_AS 512MB）；一旦触发 subprocess.TimeoutExpired，直接调用 os.killpg(os.getpgid(proc.pid), signal.SIGKILL) 清空整个进程组，返回 exit_code=124、summary="WATCHDOG_TIMEOUT"。

2.3 ASTPolicyInspector 与 IntegrityMonitor

  • 静态 AST 语法与策略守卫：除了 ast.parse 拦截 SyntaxError 外，在启用 strict_ast=True（内置 4 个算例默认开启）时，ASTPolicyInspector.inspect 会扫描抽象语法树，阻断高危导入（os、subprocess、sys、ctypes、socket、importlib、pickle 等）以及高危内建调用（eval、exec、compile、__import__、open、breakpoint）。任何落盘写入均走 .acs_tmp_<pid> + os.replace 原子替换。
  • SHA-256 门禁完整性核验：IntegrityMonitor 在代理初始化时记录所有受保护测试与 Holdout 文件的 SHA-256 摘要，每次 ToolBox.run_tdd_gate 执行前后均会校验一次；一旦发现外部篡改或文件缺失，立即抛出 IntegrityViolationError 并触发回滚。

2.4 诚实标注物理隔离边界

在工程上必须把话说透：这套沙箱属于用户态应用与子进程级别的防误改/防越权隔离，并不包含内核级容器或虚拟机隔离（如 Linux namespaces、seccomp 或 Docker）。 如果要直接运行完全不可信的第三方恶意仓库，生产部署时仍应把 ACS-Agent 放进容器或独立虚拟机内运行。

三、 ReAct 多文件协同、双协议降级与防退化闭环

3.1 Patch / ReAct 双模工具链（src/tools.py & src/agent.py）

初版原型只能对单个文件整段覆写，一旦任务涉及跨模块调用（例如 Case 4 需要同时理解并修改 precision.py 和 scheduler.py），单文件提示词就力不从心了。

新版 CodeIterationAgent 支持 agent_mode 在 "patch"、"react" 与 "auto"（当 len(writable_files) > 1 时自动启用 ReAct）之间切换，在 src/tools.py 中暴露了 6 个严格受控的沙箱工具（故意不暴露自由 Bash 执行工具）：

工具名 作用域与安全约束
list_files 列出工作区可见文件，自动跳过内部目录并过滤隐藏 hidden_files
read_file 按行号范围读取允许文件（拒绝越界路径与隐藏 Holdout）
search_code 在可见文件中按正则或子串搜索上下文（最多返回 40 条命中）
patch_file 精确查找唯一片段并替换（仅限 writable_files），落盘前校验 AST
write_file 原子覆写授权的 writable_files（落盘前校验 AST 与策略）
run_tests 触发 IsolatedTestRunner 在临时只读沙箱中跑门禁并返回结构化统计与切片

3.2 双协议自动降级与本地算力预设（src/llm_backend.py）

实战中对接不同推理后端经常踩一个坑：云端 API 支持标准 OpenAI tools 函数调用，但不少本地轻量网关或特定推理服务只要请求体里带了 tools 字段就会直接返回 HTTP 400。

LiveLLMClient.chat_step 为此做了自动协议降级：

  1. 默认优先发送带 tools 与 tool_choice="auto" 的原生 Function Calling 请求；
  2. 若服务端返回 HTTP 400，自动剥离 tools 参数、将 self.enable_native_tools 置为 False 并重发，后续自动切换为解析文本指令 [TOOL_CALL] {"name": ..., "arguments": {...}} [/TOOL_CALL]；同时兼容提取 DeepSeek-R1 等推理模型的 <think>...</think> 思考段；
  3. 内置 HARDWARE_PRESETS（kunlun-gateway、ollama、vllm、dashscope、deepseek、openai）以及 /v1/models 在线探测函数 probe_llm_endpoint，本地无真实 API Key 时自动以 "EMPTY" 占位访问本地 Token 工厂。

3.3 评分防退化回滚、停滞熔断与 Holdout 验收

自主过夜最怕两件事：一是改第 3 个测试时把前 2 个原本通过的测试改挂（Regression）；二是陷入同一种错误无限空转（Stall）。

  • 最佳快照追踪与退化回滚（src/checkpoint.py）：agent.py 定义了测试评分元组 _score_test_result = (passed_flag, passed_count, -failed_count)。每轮门禁后，FileSnapshotManager 会和历史最高分快照 best_checkpoint 比对；一旦出现分数倒退（例如通过数下降），立刻调用 restore_best() 把授权文件恢复到历史最优状态，记录 rollbacks 次数并在下轮提示词注入警告。
  • 防停滞熔断（Patch 模式）：在 _run_patch_loop 中，系统对 (state_hash, error_signature) 做频次统计；同一代码状态与错误指纹连续出现 2 次注入反思警示，累计出现 3 次则直接以 status="STALLED" 提前退出，把问题留给晨间人类工程师，避免整晚空烧 Token（补充说明：ReAct 模式 _run_react_loop 当前主要通过 max_tool_steps、max_iterations、空轮次上限 empty_turns >= 2 以及 rollback_on_regression 控制收敛边界）。
  • 隐藏 Holdout 防过拟合门禁：当且仅当可见测试全绿后，CodeIterationAgent 才会执行 _run_holdout_if_configured()（此时传入 include_hidden=True）；如果出现“背过了可见测试但过不了 Holdout”（如把 double(x) 写死 return 4），直接以 HOLDOUT_FAILED 拦截交付。

四、 24h「碳硅接力」编排器与零依赖实时工作台

4.1 跨任务全量回归与晨间交接简报（src/relay.py + run_relay.py）

单任务闭环之上，src/relay.py 实现了面向多任务工程队列的 RelayOrchestrator：

  1. 预算与连续熔断护栏：按顺序执行 relay_plan.json 中的 RelayTask 队列，受 max_total_seconds 墙钟预算（超限标记 SKIPPED_BUDGET）与 max_consecutive_failures 连续失败熔断器（超限标记 SKIPPED_CIRCUIT_BREAKER）约束。
  2. 跨任务回归守卫与自动回滚：每个任务开始前都会保存一份 pre_task 快照；当任务本地门禁与 Holdout 通过后，编排器会遍历此前所有已通过任务重跑它们的测试门禁与 Holdout（_run_regression_gates）。哪怕后一个任务修通了自己却把共享模块改崩导致前序任务挂掉，系统也会立刻恢复 pre_task 快照并标记 REGRESSION_ROLLED_BACK。
  3. 隔离分支与三件套交接产物：若开启 --git-branch，GitRelayManager 会拉出独立的 acs-relay/<run_id> 分支为每个通过任务打上里程碑提交；运行全程写入只追加的 audit_events.jsonl 事件账本，结束时自动产出 handover_summary.json 与可直接给白天工程师接续的 HANDOVER_REPORT.md（含每个任务的收敛状态、SHA-256 完整性、Holdout/回归状态、Commit SHA 与待人工介入列表）。

4.2 零依赖 HTTP + SSE 双模工作台（run_web.py + web/index.html）

为了在黑客松现场或无外网环境直接拉起面板，我放弃了原来的外部前端框架依赖，直接用 Python 标准库 ThreadingHTTPServer 写了 run_web.py 与原生前端 web/index.html：

  • 通过 /api/jobs + /api/jobs/<job_id>/events 提供 Server-Sent Events (SSE) 实时流式推送；
  • 支持 单任务 ReAct 闭环（可选内置 Case 1–4 或任意本地自定义工作区/可写文件/Holdout 路径）与 24h 夜间接力队列 双工作台切换；
  • 顶部集成端点预设下拉与 /api/probe 在线模型列表探测，夜间接力结束后可在界面内直接预览并下载 HANDOVER_REPORT.md。

五、 基准重构与实测验证（Proof of Work）

这次把之前四个“不够硬”的算例全部重写并加严了校验门槛，同时新增了多文件协同算例 Case 4：

Case 2 benchmarks/case2_vector_scale (kernel.py) 使用 struct.pack("!f", ...) 做真实 IEEE-754 float32 比特级 0-ULP 距离对齐（包含 1e-7 量级测试，直接打死 round(..., 6) 截断投机）、形状校验与 NaN/Inf 检查 test_kernel.py (7 项)

5.1 23 项单元测试与对抗性自检实测

在仓库根目录执行 python3 -m unittest discover -s tests -v，23 项测试在 6.003s 内全部通过（OK）：

关于验证口径的严格声明（避免混淆概念）：

  1. Offline Mock 不等同于大模型未知题推理能力：DeterministicMockLLM（deterministic-pipeline-mock-v2）只对内置 4 个算例返回预设补丁或固定工具调用序列，遇到未知任务会直接返回 # Unchanged 并以 MOCK_UNSUPPORTED_TASK 退出。因此 --mode mock 证明的是控制流、沙箱、回滚、回归校验与交接报告流水线没有 Bug；真正的自主推理评测必须使用 --mode live 接入真实模型（kunlun-gateway / ollama / vllm / 云端 API）检验。
  2. Case 2 的 0-ULP 口径范围：这里的 0-ULP 指的是用 struct.pack("!f", ...) 构造的标量/列表级 IEEE-754 float32 比特对齐参考检查，用来封杀 round(..., 6) 这类精度作弊，而非 GPU/NPU 底层汇编算子吞吐测试。

六、 已知边界与下一步演进

重构到这一版，这套架子已经可以稳稳撑起一场黑客松或小型仓库的“碳硅接力”演示与现场联调，但仍然有三块清醒的工程边界记在这里：

  1. 现场真实大模型长程泛化评测待补实据：目前通过本地模拟 OpenAI HTTP Server 验证了协议栈在未知题目（TokenBucket、clamp）上的闭环调度；后续接入现场真实模型（如白泽全感、Qwen2.5-Coder、DeepSeek 等）跑大型多模块仓库时，上下文窗口裁剪策略、工具调用失败重试以及真实收敛率与 Token 成本还需要实测调优。
  2. 用户态沙箱与操作系统级容器的配合：PathGuard + 临时只读副本 + 环境变量脱敏 + python -I + rlimit 能够可靠防止大模型自身幻觉误改测试或一般路径越权，但若用于不可信第三方代码执行，仍应配合 Docker / Linux namespaces 等内核隔离手段。
  3. AST 严格策略白名单与多语言扩展：strict_ast=True 目前会静态禁止 os/subprocess/open/eval 等导入与调用，非常适合纯算法/纯逻辑内核；如果工程任务确实需要合法读写磁盘配置文件或运行 C++/HIP 编译门禁，需要针对性放开 strict_ast 或扩展对应工具链适配器。

写完这轮重构最大的感受依然没变：把大模型接进终端循环只需几十行代码，真正值钱、也最花精力的，是外围那一层冷酷无情、可审计、可回滚、绝不放水的软件工程契约。 只有把沙箱、门禁、回滚和交接账本先建牢，人类才敢放心地把电脑留给 AI 跑过一整夜。
